# FRONTLINE: Five Fronts — многопользовательский FPS для Roblox

Весь игровой текст на английском. Карты, оружие и UI создаются кодом при запуске сервера
(процедурно, из собственных деталей — без чужих моделей и логотипов).

## Как открыть

**Вариант 1 — готовый файл.** Откройте `FrontlineFPS.rbxlx` в Roblox Studio.
После правок кода пересоберите его:

```bash
python3 tools/build_place.py
```

**Вариант 2 — Rojo.** `default.project.json` уже настроен: `rojo serve` и подключитесь плагином.

## Как тестировать в Studio

- **Play** — один игрок: лобби → встать на площадку карты → через 10 с матч.
- **Test → Clients and Servers → 2–4 игрока** — проверка команд, урона, убийств, пьедестала.
- В Studio матчи идут на том же сервере (режим `Local`), каждая карта в своей точке мира.
- Без доступа к API Studio выдаёт **временный профиль на 500 очков**, который не сохраняется.
  Чтобы проверить сохранение: опубликуйте место и включите *Game Settings → Security →
  Enable Studio Access to API Services*.

## Публикация (настоящий мультиплеер)

1. Опубликуйте место. В опубликованной игре режим автоматически становится `Teleport`:
   лобби резервирует отдельный сервер на каждый матч (`TeleportService:ReserveServer`),
   свободные слоты в идущих матчах ищутся через `MemoryStoreService`.
2. Включите API Services (DataStore, MemoryStore). Teleport между местами одной игры работает по умолчанию.
3. Один place используется и как лобби, и как сервер матча. Для отдельных мест задайте
   `LobbyPlaceId` / `MatchPlaceId` в `Config.Matchmaking`.

## Управление

| | ПК | Телефон/планшет |
|---|---|---|
| Движение / прыжок | WASD / Space | джойстик Roblox / кнопка прыжка |
| Прицеливание | мышь | свайп по правой половине экрана (и по кнопке FIRE) |
| Огонь | ЛКМ | FIRE (две кнопки) |
| Прицел AWP / очередь Glock / удар ножом | ПКМ | AIM |
| Перезарядка | R | R |
| Оружие | 1 / 2 / 3, колесо, Q | SWAP, KNIFE |
| Магазин оружия (только на спавне) | B | SHOP в верхней панели |
| Таблица / настройки | Tab / P | SCORE / SETTINGS |

## Структура

```
src/ReplicatedStorage/Shared         Config, MapData, SkinData, Net (все Remote), Sounds, Util, Signal
src/ReplicatedStorage/WeaponModules  WeaponData (характеристики), WeaponModels (модели + скины)
src/ServerScriptService/Main         определение роли сервера и связка сервисов
  Services/  PlayerDataManager, MatchManager, TeamManager, SpawnManager, WeaponServer,
             CombatServer, RewardManager, SkinShopServer, LobbyService, MatchRegistry, RateLimiter
  Builders/  Builder, MapKit, LobbyBuilder, PodiumBuilder, MapLoader, Maps/{Forest, ModernCity,
             BrickCity, Egypt, Maya}
src/StarterPlayerScripts/ClientMain  + Controllers/ (HUD, WeaponController, WeaponShopUI, SkinShopUI,
             LobbyUI, ResultsUI, MobileControls, SettingsController, Camera/Lighting/Input/Effects…)
```

Интерфейсы (`MainMenu`, `HUD`, `WeaponShop`, `SkinShop`, `ResultsUI`, `SettingsUI`) создаются
кодом в PlayerGui, а не лежат в StarterGui. Папки `UIAssets`/`Animations` не созданы: всё
генерируется кодом, пустые папки были бы фиктивными.

Все числа (длительность матча, награды 100/60/30, лимит игроков, задержка респауна и т.д.)
находятся в `src/ReplicatedStorage/Shared/Config.lua`; характеристики оружия — в `WeaponData.lua`.

## Безопасность

Сервер проверяет: выбор оружия и нахождение на спавне, скорострельность (интервал +
окно в 1 с), патроны, перезарядку, время доставания, позицию выстрела, направление,
попадание относительно серверной позиции цели, стены на линии огня, команду, защиту
после спавна, авторство убийства, цены и владение скинами, награды (один раз на матч по ID
матча — в памяти сервера и в профиле). Все Remote ограничены по частоте. Данные
сохраняются через `UpdateAsync` с блокировкой сессии; при ошибке загрузки профиль
никогда не перезаписывается значениями по умолчанию.

## Автотесты

В `tests/` — имитация движка Roblox (виртуальное время, экземпляры, CFrame, DataStore,
Remote) и 8 наборов тестов: сборка всех карт/лобби/пьедестала/оружия, полная симуляция
сервера (очередь → матч → стрельба/нож/эксплойты → 10 минут → пьедестал/награды →
лобби/продолжить → скины → сохранение → сбой DataStore), Teleport-режим лобби и сервера
матча, загрузка клиента на ПК и на телефоне, проверка всех звуков.

```bash
LUAU=/путь/к/luau python3 tests/run_tests.py
```

`luau` берётся из https://github.com/luau-lang/luau/releases. Текущий результат: 333 проверки, 0 ошибок.

## Известные ограничения

- **Тесты не заменяют Studio.** Мок проверяет логику и отсутствие ошибок выполнения, но не
  внешний вид, физику, реальную стрельбу по движущимся целям и производительность. Сначала
  пройдите игру в Studio с 2–4 тестовыми клиентами.
- **Звуки.** Все звуки собраны только из 11 аудиофайлов, встроенных в клиент Roblox
  (`content/sounds`, сверено с манифестом файлов клиента), поэтому битых ссылок нет:
  выстрелы — укороченный и перепитченный взрыв (у каждого оружия свой тон, длина и
  искажение, у USP-S/M4A1-S приглушённый), щелчки затвора и магазина — фрагменты шагов,
  попадания/убийства/UI — тональные «бипы», боль и смерть — `ouch.ogg`/`oof.ogg`.
  Музыка пьедестала — собственная секвенсорная мелодия (мелодия, бас, бочка, хай-хэт)
  из тех же файлов. Это рабочая замена, а не студийные звуки: для настоящих выстрелов и
  музыки вставьте свои ID в `Config.Sounds.Overrides` / `PodiumMusicId`.
  Тест `tests/sounds_test.lua` упадёт, если появится ссылка на непроверенный файл.
- **Анимации оружия** процедурные (вид от первого лица, перезарядка с магазином, затвор, нож),
  смерть — рэгдолл. На пьедестале используются стандартные эмоции Roblox (cheer/wave/dance)
  с запасной анимацией прыжка.
- Качество графики Roblox скрипты менять не могут; настройка *Effects Quality* отключает тени,
  частицы, огонь и постобработку.
